# Как устроена админка

Шпаргалка, чтобы добавить новый раздел, не вспоминая всё заново.
Разделы новостей и стримов сделаны по этому шаблону — можно подглядывать.

---

## Главное про shadcn

**Это не библиотека, а генератор кода.** `bunx shadcn add input` не ставит
зависимость — он кладёт файл `src/components/ui/input.tsx` в твой проект.
Дальше это обычный твой компонент: можно открыть, почитать, поправить.
Никакого «магического» слоя, который что-то скрывает.

Отсюда два следствия:

- Обновлений «само собой» не будет. Захочешь новую версию — перегенеришь файл.
- Если компонент ведёт себя странно, ответ лежит в его исходнике, а не в документации.

Стили берутся из переменных в `src/app/globals.css` (`--primary`, `--border`,
`--muted-foreground` и прочие). Менять цвет кнопки правкой самой кнопки не надо —
меняй переменную, и поменяется везде.

## Рецепт раздела: четыре файла

```
src/app/admin/<раздел>/
    actions.ts        создать / обновить / удалить
    page.tsx          таблица со списком
    new/page.tsx      страница создания
    [id]/page.tsx     страница правки

src/components/admin/<Раздел>Form.tsx    одна форма на создание и на правку
```

Форма **одна**, а не две. Отличаются они только тем, что подставлено в поля
и какое действие вызывается. Две почти одинаковые формы — верный способ
поправить одну и забыть про вторую.

## Скелет `actions.ts`

```ts
'use server';

import { z } from 'zod';
import { redirect } from 'next/navigation';
import { revalidatePath } from 'next/cache';
import { auth } from '@/src/auth';
import { prisma } from '@/src/lib/prisma';

// 1. Проверка прав — в КАЖДОМ действии.
//    'use server' превращает функцию в сетевой адрес, на который можно
//    постучаться напрямую, минуя интерфейс. Middleware охраняет страницы,
//    а не действия. Кнопку можно не нажимать — запрос всё равно послать.
async function проверитьДоступ() {
    const сессия = await auth();
    if (!сессия?.user?.email) throw new Error('Нет доступа');
}

// 2. Схема формы. ВСЁ из формы приходит строкой — даже числа и галочки.
const Форма = z.object({
    название: z.string().trim().min(1).max(150),
    число: z.coerce.number().int().min(0),   // coerce: строка -> число
    галочка: z.boolean(),
});

function разобратьФорму(form: FormData) {
    return Форма.parse({
        название: form.get('название'),
        число: form.get('число'),
        // Невыбранная галочка НЕ приходит в форме вообще, а не приходит как false
        галочка: form.get('галочка') === 'on',
    });
}

// 3. После изменения — обновить страницы, которые эти данные показывают.
//    Иначе публичный сайт останется с кэшем и изменения появятся через час.
function обновитьСайт() {
    revalidatePath('/');
    revalidatePath('/нужная-страница');
    revalidatePath('/admin/<раздел>');
}
```

Дальше `создать`, `обновить`, `удалить` — по три строки каждая.
`redirect()` в конце создания и правки, у удаления его нет: список
перерисуется сам после `revalidatePath`.

## Компоненты: что чем

### Поле ввода

```tsx
<div className="space-y-2">
    <Label htmlFor="имя">Подпись</Label>
    <Input id="имя" name="имя" required defaultValue={значение ?? ''} />
    <p className="text-xs text-muted-foreground">Пояснение под полем</p>
</div>
```

`id` и `htmlFor` должны совпадать — тогда клик по подписи ставит курсор в поле.
`name` — под этим именем значение придёт в `form.get()`.

**`defaultValue`, а не `value`.** С `value` React считает поле управляемым
и требует обработчик изменений, то есть клиентский компонент. Нам это не нужно:
форма отправляется целиком на сервер.

### Многострочное поле

```tsx
<Textarea id="text" name="text" rows={10} defaultValue={...} />
```

### Переключатель

```tsx
<Switch id="флаг" name="флаг" defaultChecked={значение ?? false} />
```

Работает как обычный чекбокс: включён — придёт `'on'`, выключен — не придёт ничего.

### Выпадающий список

Компонента `Select` мы не ставили: обычный `<select>` работает без
клиентского JavaScript, а стили ему можно дать те же. Пример со странами —
в `StreamForm.tsx`.

### Кнопка

```tsx
<Button type="submit">Сохранить</Button>
```

**А вот ссылка со стилями кнопки — иначе:**

```tsx
<Link href="/куда" className={buttonVariants({ variant: 'ghost' })}>Отмена</Link>
```

Не `<Button render={<Link/>}>` — Base UI ждёт внутри настоящий `<button>`,
а ссылка это `<a>`. Он ругнётся в консоли, и по делу: у кнопки и ссылки
разное поведение с клавиатурой.

Если к варианту нужно добавить свои классы:

```tsx
className={cn(buttonVariants({ variant: 'ghost', size: 'sm' }), 'mb-3 -ml-2')}
```

`cn` из `@/src/lib/utils` — он умеет разрешать конфликты классов Tailwind.

### Таблица

```tsx
<Card className="overflow-hidden p-0">
    <Table>
        <TableHeader>
            <TableRow><TableHead>Столбец</TableHead></TableRow>
        </TableHeader>
        <TableBody>
            <TableRow><TableCell>значение</TableCell></TableRow>
        </TableBody>
    </Table>
</Card>
```

`p-0` у карточки — чтобы таблица прилегала к краям.
`className="max-w-0 truncate"` у ячейки — чтобы длинный текст обрезался,
а не разъезжал таблицу.

### Значок статуса

```tsx
<Badge variant="secondary">на сайте</Badge>
<Badge variant="outline">черновик</Badge>
```

### Кнопка удаления с подтверждением

Готовая, `src/components/admin/DeleteButton.tsx`:

```tsx
<DeleteButton
    название={запись.название}
    что="Уровень"
    action={async () => {
        'use server';
        await удалитьЗапись(запись.id);
    }}
/>
```

## Три вещи, на которых легко споткнуться

**Каждая кнопка-действие в таблице — своя `<form>`.** Вложенных форм в HTML
не бывает, поэтому «скрыть», «удалить» и прочее нельзя завернуть в одну.

**Подстановка id в действие:**

```tsx
action={обновитьЗапись.bind(null, id)}
```

`bind` подставляет первый аргумент заранее. Так id не едет скрытым полем
в форме, где его можно подменить через инструменты разработчика.

**`export const dynamic = 'force-dynamic'`** на страницах админки. Иначе Next
закэширует список, и после правки будешь видеть старое.

## Конкретно про раздел «Свой рейтинг»

Он отличается от новостей и стримов, и вот чем.

**Первичный ключ — `levelId`, а не `id`.** Смотри `prisma/schema.prisma`:
у `CommunityRank` нет отдельного идентификатора, ключ — id уровня из Global
Demonlist. Уровень не может стоять в списке дважды, и это гарантирует база.

Значит:

- в запросах `where: { levelId }`, а не `where: { id }`
- папка правки называется `[levelId]`, а не `[id]`
- `levelId` — число, из формы придёт строкой, нужен `z.coerce.number().int()`

**Проверять, что уровень существует.** Человек вводит id вручную, опечатка
вероятна. Перед сохранением стоит заглянуть в список:

```ts
const уровни = await getLevels();
if (!уровни.some((l) => l.id === данные.levelId)) {
    throw new Error(`Уровня с id ${данные.levelId} нет в списке Global Demonlist`);
}
```

Без этой проверки запись сохранится, а на сайте не покажется — `getCommunityRanking()`
такие молча пропускает. Пропажа без ошибки хуже, чем понятный отказ.

**Повторный `levelId` уронит Prisma** с ошибкой `P2002` (нарушение уникальности).
Стоит поймать и сказать по-человечески: «этот уровень уже есть в списке».

**Полей в форме четыре:** `levelId`, `position`, `requirement`, `note`.
Название, автор и превью не храним — они приходят из API по `levelId`.
Мы про это договорились, когда обсуждали, что копия чужих данных
неизбежно разъедется с оригиналом.

**Список удобно показывать с названиями.** В `page.tsx` возьми
`getCommunityRanking()` из `@/src/lib/community` — она уже склеивает
позиции из базы с данными уровней из API.

## Проверить, когда доделаешь

1. Добавить уровень → появился в списке админки и на `/levels/community`
2. Добавить его же второй раз → внятная ошибка, а не падение
3. Ввести несуществующий id (например `999999`) → отказ с объяснением
4. Поменять позицию → порядок на сайте изменился
5. Удалить → пропал в обоих местах
